# 全国版（47 都道府県）を作った（2026-09-11）

> 用語: **車道** = 地理院の道路中心線のうち軽車道・徒歩道・庭園路を除いたもの（自動車が通る道路。地理院の分類名は「通常部」）。以前の版では「通常道路」と書いていた。

川越・札幌と同じ判定を全国に広げた。単位は都道府県、分母補正は道路統計年報 2024。

## データ源の判断: experimental_bvmap のまま（B）

| 案 | 中身 | 判断 |
|---|---|---|
| A. 最適化ベクトルタイル | 全国 1 本の PMTiles（17GB）を 1 回取れば済む。ZL16 の道路中心線は experimental と線分数・延長とも完全一致 | **`medSect`（分離帯）が無い**。「60→30 変更」の km は変わらない（分離帯道路はほぼ幅員 5.5 m 以上で「不明」側）が、法令の 3 条件のうち「中央分離帯」をデータで確認したと言えなくなる → 不採用 |
| **B. experimental_bvmap** | ZL16 の 216 万タイル・16.9GB を HTTP で取る | 分離帯区分が残り、市区町村版と完全に整合 → **採用** |

取得は `make_tile_download_list.py`（mokuroku から未取得分を列挙）→ `download_tiles_all.sh`（aria2c 8 並列、WSL の ext4 に `16/x/y.pbf`）。約 105 タイル/秒で **5 時間 45 分**。欠落 0。
最適化ベクトルタイルの PMTiles も `~/gsi/` に残してあり、`03_extract_roads_gdal.py --source optimal` で比較できる。

## 抽出: Python decode をやめて GDAL の MVT ドライバ

`03_extract_roads_gdal.py`。タイルを 1 枚ずつ Python で decode すると全国で 60 時間になるので、
z/x/y に置いたタイルを GDAL 3.11 の MVT ドライバでディレクトリごと読む（`MVT:~/gsi/experimental_bvmap/16`）。川越 542 枚が 60 秒 → 3 秒。結果は完全一致。

罠:
- ルートでなく**ズームディレクトリ**（`.../16`）を開く。ルートは `metadata.json` があっても認識されなかった
- `-spat` は **EPSG:3857 で解釈される**ので `-spat_srs EPSG:4326` が要る（付けないと 0 件）
- `ogrinfo -so` は件数を数えるために全タイルを走査して終わらない
- タイル境界でクリップされて点になった線分があるので `-nlt MULTILINESTRING -skipfailures`
- WSL の GDAL に Parquet ドライバが無いので出力は FlatGeobuf

都道府県は県境でのクリップをやめ、線分の代表点が県内かで割り当てる（埼玉 128 万本で 20 分 → 秒）。
05 は Parquet を読み、FlatGeobuf（tippecanoe が直接読める）で出す。1 県 2〜20 分、47 県で約 5 時間（北海道 15 分、兵庫 19 分）。

## 落ちたところ

JARTIC の面規制（ゾーン30 など）に**自己交差した多角形**が混ざっており、交差計算が `TopologyException: side location conflict` で落ちた（宮城・東京・福岡など 16 県）。`shapely.make_valid` を通してから使う。

## 結果

| | km |
|---|---|
| 地理院の道路中心線（47 県合計） | 2,297,024 |
| うち車道（ftCode 2701–2704） | 1,969,106 |
| 道路統計年報の実延長（道路法上の道路） | 1,136,668 |
| **60→30 に変わった（推定）** | **1,534,635** |

| 割合 | 値 |
|---|---|
| 60→30 変更 / 地理院の車道 | 77.9% |
| 60→30 変更 / 道路法上の道路に換算（下限〜上限） | **62.5〜77.9%** |
| 構造的に対象（幅員 5.5 m 未満・分離帯なし）/ 道路法道路に換算 | 71.8〜83.4% |
| （参考）道路統計年報 表15 の幅員 5.5 m 未満 | **71.0%** |

記事の「約 7 割が対象」は、道路統計年報の幅員 5.5 m 未満 71.0% と一致する。こちらの「構造的に対象」も道路法道路に換算すると 72〜83% で整合する。
実際に速度が変わったのは、そこから既存の標識・ゾーン規制を除いた **6〜8 割**。

地理院の中心線は道路統計より **83 万 km（+73%）多い**。私道・農道・林道の分で、川越（+29%）・埼玉（+28%）より全国では比率が高い（山間部の林道・農道）。この超過分を全部「変更」とみなして引いたのが下限。

都道府県別は [`out/national/prefectures.md`](../out/national/prefectures.md)。

### 目立つ県

- **兵庫県**: 変更 48%（車道比）と全国最低。40 km/h の**区域規制**が 18 面 2,321 km²（県の 27%）あり、23,126 km が「規制あり:ゾーン40」に入る。兵庫県警の面的な速度規制の運用によるもので、データどおりなら区域内はもともと 40 で変わらない。要確認事項として残す
- **東京都**: 変更 59%。標識 30 と ゾーン30 で 6,800 km が既に 30
- **大阪府**: 変更 64%。標識 20・ゾーン20 が 2,600 km
- **北海道**: 中心線 183,236 km で最大。道路統計 85,047 km に対し市区町村道の超過 71,136 km（林道・農道）。下限 48.8%
- 高知・和歌山・徳島・愛媛など四国・紀伊は 84〜87% と高い（狭い道が多く規制が少ない）

下限（超過分を全部変更とみなす）は超過が大きい県では極端に低くなる（兵庫 3.8%、大阪 26.6%）。分母の不確かさの幅として読む。

### 全国 PMTiles のズーム域

最初は市区町村版と同じ Z9–16・間引きなしで作った（8.8GB、3,583 万本、24 分）。中身は正常だが、
低ズームのタイルが大きすぎた:

| タイル | 本数 | gzip 後 | 展開後 |
|---|---|---|---|
| z9 東京圏（454/201） | 197 万本 | 38 MB | 107 MB |
| z10 東京（909/403） | | 11 MB | 29 MB |
| z11 東京（1818/806） | | 4.6 MB | 12 MB |
| z12 東京（3634/1612） | 5 万本 | 1.1 MB | 2.7 MB |

z9 で東京圏を開くと 1 画面で 100 MB 超・数百万本になりブラウザが固まる。間引き・まとめはしない方針なので、
**全国版は Z12 から**作ることにした（市区町村版は Z9 のまま）。低ズームでは背景地図だけが見え、Z12 に寄ると道路が出る。
Z12–16 版は **6.49GB、175.8 万タイル**、z12 の東京タイルは gzip 1.1 MB（tippecanoe 24 分）。
